## 二、整條流程

```
衛星影像（數字陣列）
  │
  ├─ to_db、lee_filter ............ 前處理：去雜訊、換成 dB
  │
  ├─ flood_vote ................... 淹水（三法投票）
  ├─ lodging_map .................. 倒伏（VH 變化）
  ├─ buried_map ................... 埋沒、流失（同調性下降）
  │
  ├─ inset_mask、parcel_features .. 像素 → 每塊田一列數字
  ├─ add_ndvi_z ................... 植生受損（和沒事的同作物田比）
  │
  ├─ guess_crop ................... 猜作物
  ├─ estimate_loss ................ 估損失區間
  ├─ three_gates .................. 三道關卡 → A／B／C
  │
  └─ evidence_report .............. 存證報告
```

`analyse(sc)` 把前處理、判讀、坵塊化包在一起；`classify_parcels(rows)` 把猜作物、估損失、三道關卡包在一起。平常用這兩個就夠了，想了解細節再看裡面的個別函式。

## 三、資料長什麼樣子

所有影像都是 numpy 陣列，形狀是 `(列, 欄)`；有好幾期的是 `(期數, 列, 欄)`。

| 名稱 | 形狀 | 單位 | 說明 |
| --- | --- | --- | --- |
| `vv_pre`、`vh_pre` | (6, H, W) | 線性強度 | 災前 6 期雷達 |
| `vv_post`、`vh_post` | (H, W) | 線性強度 | 災後雷達 |
| `coh_pre`、`coh_post` | (H, W) | 0–1 | 干涉同調性（真實資料這次沒有下載） |
| `ndvi_pre` | (6, H, W) | −1–1 | 災前 6 期 NDVI |
| `ndvi_post` | (H, W) | −1–1 | 災後 NDVI，被雲遮的地方是 `NaN` |
| `parcel` | (H, W) | 整數 | 每個像素屬於哪一塊田，0 是田埂、道路 |

坵塊化之後，每一塊田變成一個 `dict`（程式裡叫 `r`，整批叫 `rows`），常用的欄位：

| 欄位 | 意思 |
| --- | --- |
| `flood_frac`、`lodge_frac`、`buried_frac` | 這塊田有多少比例的像素判為淹水、倒伏、埋沒（0–1） |
| `ndvi_z` | NDVI 比同作物沒事的田低幾個標準差，負數越大越糟；被雲遮是 `NaN` |
| `cloud_frac` | 被雲遮的比例 |
| `n_pix` | 內縮後剩幾個像素 |
| `pred_crop`、`declared_crop` | 判釋的作物、農民申報的作物（0 水稻、1 香蕉、2 果樹） |
| `applied` | 農民有沒有申請 |
| `q10`、`q50`、`q90` | 損失區間（下限、中間、上限） |
| `grade`、`reasons` | A／B／C 和原因碼 |

## 四、函式說明

### 前處理

**`to_db(lin)`**

把雷達的線性強度換成 dB：`10 × log10(值)`。每差 10 倍，dB 就差 10。水面約 −20 dB，農田約 −10 dB。

```python
sky.to_db(np.array([0.01, 0.1, 1.0]))     # → [-20, -10, 0]
```

**`lee_filter(img, size=5)`**

去掉雷達的斑點雜訊。雷達影像天生顆粒很粗，同一塊田的像素忽亮忽暗。Lee 濾波在平坦的地方取周圍平均，在邊界附近保留原值，所以田和水的交界不會糊掉。

- 輸入：**線性強度**的 2D 陣列（不是 dB）
- 輸出：同樣大小，仍是線性強度
- `size` 是視窗大小，越大越平滑，但小田的細節也會被抹掉

```python
clean_db = sky.to_db(sky.lee_filter(vv_post))     # 先濾波、再轉 dB，順序不能反
```

### 判讀

**`otsu(values)`**

自動找出把數值分成兩群的最佳門檻，用來分「水」和「陸地」。回傳一個數字（dB）。

要注意：影像裡海面太多時，門檻會被拉高，把潮濕的田也算成水。丹娜絲真實資料就遇到這個情況（算出 −11 dB），所以 `flood_vote` 有 `max_thr_db` 參數可以設上限。

**`flood_vote(vv_pre_db, vv_post_db, max_thr_db=None)`**

淹水三法投票。三個方法各自判斷，至少兩個同意才算淹水：

| 方法 | 判斷 |
| --- | --- |
| 法 1 水體門檻 | 災後 VV 低於 Otsu 門檻 |
| 法 2 變遷偵測 | 災後比災前最近兩期暗 3 dB 以上 |
| 法 3 時序異常 | 災後低於災前 6 期平均 3 個標準差 |

災前就已經是水的地方（海、魚塭、河道）不算淹水。

- 輸入：災前 `(6, H, W)` 和災後 `(H, W)`，都是 **dB**
- 輸出：`flood`（True／False 陣列）和 `detail`（字典，有三個方法各自的結果、`threshold_db` 門檻、`perm_water` 災前就是水的範圍）

```python
flood, detail = sky.flood_vote(vv_pre_db, vv_post_db, max_thr_db=-15)
print(detail["threshold_db"])          # 實際用的門檻
print(flood.sum() * 100 / 1e4, "公頃")   # 每像素 10 × 10 米
```

**`lodging_map(vh_pre_db, vh_post_db, flood)`**

倒伏。看 VH 在災後和災前最近兩期之間變了多少 dB，絕對值超過 2.5 dB 就算。水稻倒伏 VH 會變亮，香蕉、果樹冠層倒塌會變暗，兩種都算。已經判為淹水的像素不重複算。最後用 3×3 中位數平滑，去掉零星的單點。

- 輸出：`lodge`（True／False）和 `ratio`（每個像素變了幾 dB）

**`buried_map(coh_pre, coh_post, flood)`**

埋沒、流失。同調性代表「兩次拍攝之間地表有沒有變」，接近 1 是沒變。災後降到 0.5 以下、而且比災前少 0.3 以上，表示地表整個換了（被泥沙蓋住、被水沖走）。淹水也會讓同調性下降，所以淹水像素排除。

### 坵塊化

**`inset_mask(labels)`**

每塊田向內縮一圈（1 像素，約 10 米）。邊緣像素常混到田埂或隔壁田的訊號，先拿掉比較準。太窄的田會整塊被吃光，之後在關卡 1 列 C（小田）。

**`analyse(sc)`**

一次做完前處理、三種判讀、坵塊化。回傳 `maps`（各種像素結果）和 `rows`（每塊田一個 dict）。

```python
sc = sky.simulate_scene(seed=7)     # 模擬一個工況；seed 換數字就是另一個工況
maps, rows = sky.analyse(sc)
```

**`add_ndvi_z(rows, crop_key)`**

植生受損分數。每塊田的 NDVI 下降量，和「同作物、而且雷達看起來沒事的田」比較，算出低了幾個標準差。全區都降一點（季節、收割）會被抵銷，只留下特別異常的田。參考組不能放受損田，否則受損訊號會被稀釋，這是開發時實際踩過的問題。

### 分級

**`guess_crop(r)`**

用災前 6 期猜作物（規則版，正式系統換成時序 Transformer）：NDVI 從第 1 期到第 6 期上升超過 0.2 → 水稻；否則 VV 平均高於 −9 dB → 香蕉；其他 → 果樹。

**`estimate_loss(r)`**

估損失區間，回傳 `(下限, 中間, 上限)`。

- 中間值：取淹水、倒伏、埋沒三種訊號中最嚴重的一個（淹水比例 × 作物權重、倒伏比例 × 0.75、埋沒比例 × 0.95）
- 雷達完全沒看到變化時，改用 NDVI 分數
- 誤差範圍：雷達有訊號 ±15%，沒訊號 ±5%，被雲遮一半以上再加 5%

```python
sky.estimate_loss(dict(pred_crop=0, flood_frac=1.0, lodge_frac=0, buried_frac=0,
                       ndvi_z=-10, cloud_frac=0))
# → (0.85, 1.0, 1.0)：整塊淹水的水稻，損失 85%～100%
```

**`three_gates(r)`**

三道關卡，回傳 `(等級, 原因碼清單)`。任一關沒過就是 C。

| 關卡 | 檢查 | 沒過的原因碼 |
| --- | --- | --- |
| 1 影像信心 | 像素夠多、地籍對位可靠、雷達和光學說法一致 | C1 |
| 2 遠離門檻 | 下限 ≥ 40% → A；上限 ≤ 10% → B；其他 → C | C2 |
| 3 與申報一致 | 作物和申報相同；有申請卻沒變化的不能給 B | C3 |

`tutorial.py` 第 10 段列了六種情況各會得到什麼，可以直接看。

**`classify_parcels(rows)`**

一次做完猜作物、NDVI 分數、損失區間、三道關卡，結果直接寫回每個 `r`。

```python
sky.classify_parcels(rows)
for r in rows:
    print(r["id"], r["grade"], f"{r['q10']:.0%}～{r['q90']:.0%}", r["reasons"])
```

**`classify_ponds(sc, maps)`**

魚塭分級。在養強證據（災前有水、偵測到水車、有放養申報）加上直接受災（整池溢堤或池水少一半），而且有申請 → A；沒申請也沒任何變化 → B；其他 → C，並算出現勘優先分數（停電天數、溢堤比例、池水流失）。

### 輸出

| 函式 | 做什麼 |
| --- | --- |
| `evaluate(rows, ponds)` | 和模擬的正確答案比對，算 A、B 精確度、C 比例等。**只有模擬資料能用**，真實資料沒有正確答案 |
| `make_figures(...)` | 畫圖 D1～D4 |
| `evidence_report(sc, r, maps)` | 產生一筆存證報告（dict），含主要災害證據、影像編號、參數、SHA-256 雜湊 |

## 五、常改的門檻

都在 `skyaide_demo.py` 最上面，改了重跑就能看到分級怎麼變。

| 變數 | 預設 | 意思 |
| --- | --- | --- |
| `FLOOD_DIFF_DB` | −3.0 | 法 2：比災前暗多少 dB 算淹水 |
| `FLOOD_Z` | −3.0 | 法 3：低於災前幾個標準差算淹水 |
| `LODGE_DB` | 2.5 | VH 變化超過幾 dB 算倒伏 |
| `COH_BURIED` | 0.5 | 同調性低於多少算埋沒 |
| `GATE_A_Q10` | 0.40 | 損失下限超過多少給 A |
| `GATE_B_Q90` | 0.10 | 損失上限低於多少給 B |
| `MIN_PIX` | 5 | 內縮後少於幾個像素算小田 |

例如把 `GATE_A_Q10` 從 0.40 降到 0.30，A 會變多、C 會變少，但判錯的風險也會增加。

## 六、換成自己的資料

函式只認 numpy 陣列，不管資料從哪來。只要把影像讀成陣列、形狀對上就能用。下面是用丹娜絲真實資料跑淹水判釋的最短寫法：

```python
import numpy as np
import skyaide_demo as sky

d = np.load("real_data/danas_s1.npz")                     # fetch_crop.py 下載的
pre = [d[f"pre{i}_vv"] for i in range(6)]                 # 線性強度
post = d["post_vv"]

pre_db = sky.to_db(np.stack([sky.lee_filter(np.nan_to_num(x, nan=1e-4)) for x in pre]))
post_db = sky.to_db(sky.lee_filter(np.nan_to_num(post, nan=1e-4)))

flood, detail = sky.flood_vote(pre_db, post_db, max_thr_db=-15)
print("淹水約", round(flood.sum() * 100 / 1e4), "公頃")     # → 約 284 公頃
```

這裡算出約 284 公頃，報告寫 173 公頃，差別在 `real_danas_analysis.py` 多做了一步：把連在一起少於 20 個像素（約 0.2 公頃）的零星點去掉。

想換地點或日期，改 `fetch_crop.py` 最上面的 `BBOX`（經緯度範圍）和兩個日期就好。

## 七、常見錯誤

| 狀況 | 原因 | 解法 |
| --- | --- | --- |
| 結果全部是淹水或全部不是 | `lee_filter` 吃到 dB，或 `flood_vote` 吃到線性值 | 順序固定是：線性 → `lee_filter` → `to_db` → 判讀 |
| 出現 `nan` 相關警告、結果怪怪的 | 影像有空值（NaN），濾波時擴散開 | 濾波前先 `np.nan_to_num(x, nan=1e-4)` |
| 沿海一大片被當成「災前就是水」 | Otsu 門檻被海面拉高 | `flood_vote(..., max_thr_db=-15)` |
| 前後比對有一條條錯位 | 各期影像大小差 1～2 像素 | 下載時固定寬高（`fetch_crop.py` 已設 1600 × 1600） |
| 沒受災的稻田被判倒伏 | 拿 6 期平均當基準，把正常生長當成變化 | 程式已改成和災前最近兩期比 |
| `evaluate` 報錯找不到 `true_loss` | 真實資料沒有正確答案 | `evaluate` 只用在模擬資料 |
