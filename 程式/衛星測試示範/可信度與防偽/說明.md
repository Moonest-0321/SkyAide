# 標準作業流程原型：可信度與防偽

把 `衛星測試示範/skyaide_demo.py` 的判讀與分級包進一套作業流程（S1–S8），每一步留紀錄、可查驗。對應構想書 v7 第三章 4(2)–(4)、(7)。

## 執行

把本資料夾的 `.py` 檔和 `skyaide_demo.py`、`real_data/` 放在同一層，然後：

```
pip install numpy scipy cryptography pillow matplotlib
python sop_pipeline.py 27      # 跑一次完整流程，坵塊 27 改成裸地申請（竹塘案型）
python verify.py sop_output/reports/*.json   # 查驗報告與作業日誌
python tamper_tests.py         # 12 項竄改／偽造／品質評估測試
python credibility_eval.py     # 可信度等級與實際誤差、保形校準
python make_figures.py         # 構想書圖 15
python longterm_check.py       # 長時間對照（3 年時序）四項檢核
```

`tamper_tests.py` 的 T11 會讀 `衛星測試示範/web/img/` 的 6 張影像，路徑寫在程式裡，換電腦要改。

## 檔案

| 檔案 | 內容 |
|---|---|
| sop_pipeline.py | S1 輸入登錄 → S2 環境鎖定 → S3 計算 → S4 可信度 → S5 簽章、時戳與先行通知 → S6 公所判定 → S7 Merkle 封存 → S8 災後品質評估（qa_report.json） |
| verify.py | 查驗報告簽章、時戳、查驗碼；檢查日誌雜湊鏈；比對 Merkle 根；重算 |
| tamper_tests.py | T1–T12 測試，結果在 sop_output/tamper_results.md |
| credibility_eval.py | 10 個工況、769 筆坵塊，結果在 sop_output/credibility_eval.json |
| longterm_check.py | 3 年、每 6 天一筆的模擬時序，L1–L4 長時間對照，結果在 sop_output/longterm_results.json |
| sop_output/ | 一次執行的輸出：輸入清單、環境紀錄、49 份報告、作業日誌、批次根雜湊、信任清單 |

## 限制

- 影像是模擬資料，金鑰是本機產生的示範金鑰，時戳是模擬的。正式系統改用憑證機構簽發的憑證、公所用機關憑證、時戳用 RFC 3161 服務。
- 輸入影像檔（inputs/*.npy，約 30 MB）沒有一起放進來，執行 `sop_pipeline.py` 會重新產生；因為模擬是固定亂數種子，內容和雜湊都會一樣。
- 測試證明的是「竄改會被發現」，不是「判讀正確」。判讀精確度要等公所現勘資料。
- 照片比對門檻 16 是用這 6 張影像訂的，換成真實 App 照片要重新訂。
