# 天相星 影像處理鏈

依構想書（完整版・母檔）三、4 與技術分析的影像處理流程圖（v8_image_flow），從資料輸入一路做到災後評等。每一步都寫入監看紀錄，用 `monitor.html` 看。

## 執行

```
pip install numpy scipy scikit-learn lightgbm matplotlib cryptography
python run.py              # 內建模擬資料跑一次，約 30 秒
python run.py --seed 11    # 換一組模擬地景
python run.py --until S3-4 # 只跑到某一步
```

執行中或執行後，用瀏覽器打開 `monitor.html`（雙擊即可，不需要伺服器）。執行中每 2 秒自動更新；新的一次執行開始後重新整理頁面，就能在上方選單選到。

## 流程

| 步驟 | 做什麼 | 程式 | 構想書 |
|---|---|---|---|
| S1 資料輸入 | 登錄來源、產品編號、SHA-256，比對官方檢查碼；有效像素、數值範圍、網格；災前影像 ≤ 10 日，未過即停止 | `s1_ingest.py` | 表 37 S1 |
| S2 環境鎖定 | 程式、參數、套件版本雜湊；只用核可版本 | `s2_lock.py` | 表 37 S2 |
| P0 準備期回溯 | 以過去 3 場災害的核定清冊訓練作物判釋與損失模型；判讀元件驗證決定能否支撐 A | `p0_prepare.py` | 三、4(14) |
| S3-1 前處理 | 雷達地形正規化、Lee 濾波、dB、陰影疊置；光學 Cloud Score+ 去雲（0.60）、NDVI／NDRE／NDWI／MNDWI；夜間燈光基準 | `s3_1_preprocess.py` | 表 31 |
| S3-2 坵塊化 | 對位檢查、災前水面與非農地排除；內縮 10 米（圖解地籍 20 米）；< 5 格改用高解析；每塊田一張時序表 | `s3_2_parcel.py` | 表 31、表 32 |
| S3-3 影像判讀 | 淹水三法投票、倒伏（VH 比值＋馬可夫隨機場三級）、埋沒（同調性）、植生（扣去年同期、比同作物鄰田）、作物判釋、魚塭與停電；熱區高解析影像下單並補登 | `s3_3_interpret.py` | 表 34、表 36 |
| S3-4 損失區間 | 半經驗損傷函數＋LightGBM 分位數（10／50／90）堆疊；分組保形校準；每作物均方根誤差 > 10 只作參考 | `s3_4_loss.py` | 表 34、圖 25 |
| S4 案件分級 | 五項檢核（含 L1–L4）→ 損失區間；元件門檻；R1–R5；未申請者主動通知 | `s4_grade.py` | 表 17、39、18、42、70 |
| S5 存證報告 | 固定格式序列化、SHA-256、Ed25519 簽章、時戳、查驗碼；簽發前重驗輸入與環境；依等級發通知 | `s5_report.py` | 表 37 S5、三、4(8) |
| S6 交付公所 | 丙不交、乙參考、甲參與判定（A 自動申報）；類別不高於整體；輸出 CSV | `s6_deliver.py` | 表 19 |
| S7 封存回填 | Merkle 根；現勘回填（丙乙全部、甲 A 20% 抽查＋B、C） | `s7_seal.py` | 表 37 S7 |
| S8 評等 | 逐類別兩種 A 精確度、判定正確率、直接判定率、B 確認率，95% 下界（跨場累計）；下一場等級；偏差與缺失；日誌雜湊鏈查驗 | `s8_review.py` | 表 66、67 |

參數起始值在 `config/params.json`（表 35），S2 會鎖定並記錄雜湊。

## 監看

`monitor.html` 有四個畫面：

- **流程總覽**：每一步的狀態（完成、有警示、停止、執行中）、耗時、檢核通過數；點任一步看檢核點、指標、中間成果圖、表格、警示與執行紀錄。
- **警示**：所有未通過的檢核與警示，標明是停止、警示或只記錄。
- **坵塊追蹤**：選一塊田，看它從 S3-2 到 S7 每一步的數值、五項檢核、R1–R5、存證報告與回填；模擬資料另顯示地真值對答案。
- **作業日誌**：每一步的雜湊鏈，檢查前後鏈結。

每次執行的紀錄都在 `runs/<執行編號>/`：`monitor_data.js`（監看資料）、`img/`（中間成果圖）、`ledger.jsonl`（作業日誌）、`environment.json`、`reports/`（存證報告）、`keys/`（示範公開金鑰）、`deliver/`（交付公所的 CSV）、`batch_seal.json`、`backfill.json`。

## 資料來源

目前用 `skyaide/sources/synthetic.py` 的模擬資料：3 × 3 公里虛構農區（水稻、香蕉、麻竹筍、木瓜、山坡竹林、魚塭），產出未校正的原始產品（帶地形效應與斑點的雷達、有雲的光學、同調性、地形、夜間燈光、地籍含圖解偏移、申報含不實申請、App 照片、3 年坵塊時序），另有 3 場過去災害作為準備期資料。地真值只在 S7 模擬現勘與監看對答案時使用，處理鏈看不到。

換成真實影像時，照 `skyaide/sources/base.py` 的介面實作一個來源類別即可，流程不用改；`skyaide/sources/planetary.py` 留了接口與建議做法。

## 與構想書規格的差異（輕量可跑版）

- 淹水第三法用時序異常代替微調 Prithvi（Hugging Face 無法連線取得權重）；作物判釋用時序特徵＋隨機森林代替 Presto／Transformer；倒伏高解析語意分割以模擬的分割結果代替。三者都保留在同一位置，換模型不影響前後步驟。
- 簽章為示範金鑰、時戳為本機時間；正式系統改用憑證機構憑證、硬體安全模組與 RFC 3161。
- 模擬資料的作物判釋準確率偏高，真實影像上水稻以外作物目前分不出來（構想書已說明），屆時 P0 會自動判定「以申報為準，只查物候」。
