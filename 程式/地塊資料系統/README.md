# 天相星 地塊資料系統

參考歐盟農地坵塊識別系統（LPIS）的做法，管理地號、坵塊（實際耕作範圍）、作物、經營人與使用權，並提供災前基準的鎖定與查驗。
目前是獨立的一套，**沒有接到影像處理鏈，也沒有接到公所端、農民端網頁**；農民登錄只有資料結構與狀態，沒有登錄畫面。

## 執行

```
pip install shapely
python build_demo.py          # 產生示範資料庫 data/parcels.gpkg 與展示頁資料，約 1 秒
```

然後用瀏覽器打開 `viewer/index.html`（雙擊即可，不需要伺服器）。

命令列查詢：

```
python query.py asof P019 2025-07-06       某塊田在颱風當天的範圍、地號對應、作物、經營人、災前基準
python query.py history P001               某塊田的所有異動
python query.py cap F001 ZQ-1 2026-01-15   某經營人在某地號的可申報上限
python query.py alloc P019 2025-07-06      判讀結果怎麼分攤回各地號
python query.py verify                     查驗異動紀錄雜湊鏈與全部災前基準
```

`data/parcels.gpkg` 是 GeoPackage（OGC 標準格式，座標 TWD97 TM2，EPSG:3826），QGIS 或 ArcGIS 可直接打開；`parcels_current`、`lots_current`、`ineligible_current` 是現行圖層，`parcels`、`lots` 含全部歷史版本。

## 設計原則

1. **不覆蓋，只新增版本。** 每筆資料有生效日與失效日（空白表示現行）。地號分割、地籍重測、坵塊分割合併、租約換人，舊版本都留著，任何一天都查得回「當時」的樣子。颱風判讀用的是颱風當天的版本，不是今天的。
2. **地號是正式依據，坵塊是判讀單位。** 兩者用對應表連起來。判讀結果依「佔本田」比例分攤回地號；重疊低於 0.5% 當成邊界誤差不建對應。
3. **圖解地籍會偏移。** 坵塊有 2%–20% 落在圖解地籍的隔壁地號時，標成「疑似對位偏移」，登錄時列為範圍需確認。重測完成後重新對應，標示自動消失。
4. **災前基準鎖定後不能改。** 資料庫觸發器擋下修改與刪除；快照雜湊可隨時重算比對。災後不再量面積。
5. **所有異動都進雜湊鏈。** 展示頁可以在瀏覽器裡重算整條鏈，也能示範「改掉一筆」之後從哪裡斷掉。

## 登錄檢查規則（`lpis/core.py` 的 `submit_registration`）

| 條件 | 結果 |
|---|---|
| 該地號沒有有效使用權（例如租約已到期） | 系統已擋下 |
| 申報面積超過本筆面積 × 持分 | 系統已擋下 |
| 農路水塘佔一成以上、只租一部分、圖解地籍、申報大於有效面積 5% 以上 | 範圍需確認 |
| 其他 | 待確認 |

公所確認方式沿用公所端網頁的三種：依套疊結果確認、修正範圍後確認、排定到場確認。確認後即鎖定災前基準。

規則參數集中在 `lpis/core.py` 的 `RULES`。

## 檔案

```
build_demo.py        產生示範資料庫與展示頁資料
query.py             命令列查詢
lpis/core.py         資料表、版本管理、各項功能（ParcelDB）
lpis/gpkg.py         GeoPackage 讀寫（只用 sqlite3 與 shapely）
lpis/tm2.py          TWD97 TM2 → 經緯度
lpis/simulate.py     示範農區與時間軸
viewer/index.html    展示頁（地圖、日期拉桿、坵塊資料、登錄佇列、品質檢查、異動紀錄）
data/parcels.gpkg    示範資料庫（build_demo.py 產生）
```

## 之後要接的時候

- 地籍：改成讀地政機關提供的地籍圖檔與登記資料，呼叫 `add_lot`、`subdivide_lot`、`resurvey_lot`。
- 坵塊範圍：改成讀農業部門的坵塊圖或航照判釋成果，呼叫 `add_parcel`、`reshape_parcel`、`split_parcel`、`merge_parcels`。
- 影像處理鏈：S3-2 坵塊化改從這裡用 `as_of(坵塊, 災害日期)` 取範圍、有效面積與災前基準，判讀結果用 `allocate` 分攤回地號。
- 公所端、農民端：登錄送出呼叫 `submit_registration`，公所確認呼叫 `confirm_registration`。

以上都還沒做，等決定要耦合時再接。
